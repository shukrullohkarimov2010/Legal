# Локальные профили `legal`, `legal-strong`, `legal-fast`

Это профили Ollama поверх открытых базовых моделей: Modelfile задаёт
системный промпт и параметры генерации, веса не меняются. Юридическую
точность обеспечивает не дообучение, а поиск по кодексам РТ и проверка
реквизитов нормы — см. [`python/RAG.md`](../python/RAG.md).

| Профиль | База | Где используется | Контекст |
|---|---|---|---|
| `legal-strong` | `qwen3:8b` | анализ договоров (по умолчанию) | 16384 |
| `legal-fast` | `qwen3:8b` | чат | 8192 |
| `legal` | `llama3.1:8b` | прежний облегчённый профиль | — |

`legal-fast` переведён с `phi3` на `qwen3:8b`: phi3 слабо владеет русским
юридическим регистром, а в юридическом ответе кривая формулировка читается
как ошибка по существу. Обе рабочие роли теперь на одних весах, поэтому
Ollama не перезагружает модель при переключении между чатом и анализом.
Для слабого железа соберите профиль на `qwen3:4b`, заменив `FROM` в
[`Modelfile.legal-fast`](Modelfile.legal-fast).

## Сборка и обновление

```powershell
ollama create legal-strong -f deployment/Modelfile.legal-strong
ollama create legal-fast   -f deployment/Modelfile.legal-fast
ollama pull nomic-embed-text          # опциональный векторный слой поиска
```

Проверка правил цитирования:

```powershell
ollama run legal-strong "Назови правила точного цитирования норм права"
```

После смены профиля перезапустите `python/app.py`.

## Как обеспечивается точность ссылок

1. Фрагмент индекса — одна статья кодекса со своими реквизитами
   (кодекс, глава, номер). Реквизиты берутся из структуры документа,
   а не из текста ответа модели.
2. В контекст запроса подставляется строка
   `ПРОВЕРЕННАЯ ССЫЛКА RAG: <кодекс>, Глава N, Статья N`.
3. Системный промпт разрешает называть кодекс, главу и статью **только**
   из этой строки. Если её нет — модель обязана ответить «Точная ссылка не
   подтверждена RAG».
4. Анализ договоров работает по принципу fail-closed: без готового индекса
   Гражданского кодекса он не запускается (`ensure_contract_rag_ready`).

## Про дообучение

Автоматически менять веса после переписки нельзя: это накапливает ошибки
и неприемлемо для юридической системы. Правила отбора примеров —
в [`python/training_data/README.md`](../python/training_data/README.md).
Для качества ответов важнее поддерживать актуальность корпуса законов:
замените файлы в `storage/app/rag/` и пересоберите индекс
(`python build_rag_index.py`).

`legal-strong` не является и не может стать локальной копией облачной
модели: это открытая базовая модель, установленная на этой машине.
